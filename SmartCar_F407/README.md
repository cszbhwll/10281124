# 智能搬运小车 · STM32F407 整车程序（初赛）

适用硬件：正点原子探索者 STM32F407ZGT6，幻尔四路编码电机驱动板，4 个 25GA370 编码电机，麦轮（直径按 robot_config.h 的 WHEEL_DIAMETER_MM），3 个 ST3215（回转、肩、肘），1 个 SC09（夹爪）。
编写日期：2026-10-13。

---

## 1. 先说清楚：这套程序做到了什么，还缺什么

**已经做好的部分（代码完整，能编译，电脑模拟器里整场能跑通）：**

- 麦轮底盘：运动学、编码器里程计、平滑加减速、按坐标走位、沿车道自动规划路线（不压禁行区）
- 驱动板通信：I2C 读写幻尔驱动板
- 机械臂：ST3215 和 SC09 总线舵机通信、逆运动学（给坐标自动算关节角）、取放动作
- 整场比赛流程：读码 → 两批取放 → 码垛 → 返程；抓取/放置计数；时间不够时自动放弃剩余任务、直接返程
- 串口调试命令：上车后不用改代码，就能单独测试每个电机、舵机、走位
- 陀螺仪 MPU6050（GY-521）驱动，默认启用，掉线自动退回轮子
- 避障：8 个 VL53L0X 激光测距（经 TCA9548A 多路开关）→ 障碍物地图 → 路线被挡时刹车、绕到别的车道（见 7.1 节）

**必须在实车上完成的部分：**

| 项目 | 说明 |
|---|---|
| 标定参数 | 轮子每圈脉冲数、轮距、舵机零位、夹爪开合值等，都标了【标定】，按第 5 节做 |
| 摄像头程序 | 型号未定。单片机这边的通信协议已写好（见 `vision.h`）；相机那边的识别程序等选定型号再写 |
| 屏幕驱动 | 型号未定。写好了"后端接口"（见 `display.h`）；没接屏幕时内容打印到串口 |
| 场地坐标 | 按规则图估算，到现场实测后改 `field.c` |
| 测距传感器驱动 | `tof_vl53l0x.c` 按 Pololu 开源驱动移植，**还没在实车上验证过**。装好后先用串口命令 `tof` 看读数（5.6.1） |

**电脑模拟结果**（`sim/示例输出/批量模拟结果.txt`，按“越出车道即本轮结束”计分）：在参数完全标定正确、轮子不打滑的前提下，5 种任务码 × 2 个启停区 × 不同转盘随机情况，共 20 场：

- 全部不压线，12 次抓取全部完成
- 用时约 158~173 秒，估算得分 166~211 分，平均约 189 分
- 全部停回启停区

另有 20 场“随机障碍物”（每场 1~3 个，规则说的抽签摆放）：平均约 162 分，1 场车身碰到障碍物。障碍物多时要绕路，码垛常被时间管理放弃，所以分数比没有障碍物低。

时间偏紧：转盘等料慢时，最后 1~3 个码垛会被"时间管理"放弃，以保证按时回到启停区。

**打滑是目前最大的问题**：轮子打滑 2% 且不装陀螺仪时，十几秒就越出车道；装了陀螺仪、打滑 2% 时大多能跑完但常常停不回启停区；打滑 5% 或相机看不到圆环时会越线。实车一定会打滑，这部分要优先改进（更多依靠陀螺仪和相机修正位置）。

**模拟器不等于实车。** 模拟说明程序逻辑是对的；实车能不能跑完，要靠第 5 节一步步调。

## 3. 打开、编译、下载

1. **STM32CubeIDE**
   - 打开 File → Import → General → Existing Projects into Workspace，选择本文件夹。
   - 点锤子按钮编译。
   - 本工程**没有 .ioc 文件**，请不要用 CubeMX 重新生成代码，否则会覆盖 main.c。
2. **下载**：用 PTD01 DAP 下载器（SWD）下载，和点灯实验一样。
3. **独立启动**
   - 把开发板 BOOT0 跳线接到 GND（点灯时"复位停在内部启动程序"就是 BOOT0 没接地）。
   - 断电重启后绿灯慢闪，说明程序在运行。
4. **看日志**
   - USB 线接开发板的 USB_UART 口。
   - 串口助手（如正点原子 XCOM）设为 115200、8N1，勾选"发送新行"。
   - 能看到启动日志，输入 `help` 列出全部命令。

## 4. 接线（对照 EXPLORER V3.4 原理图选的引脚）

| 功能 | 单片机引脚 | 接到 | 注意 |
|---|---|---|---|
| 电机驱动板 I2C | PB8 = SCL，PB9 = SDA | 驱动板 IIC 口 SCL/SDA/GND | 与板载 24C02、磁力计同一总线，地址不冲突 |
| 舵机总线（ST3215 ×3 + SC09 夹爪） | PA2 = TX，PA3 = RX（USART2，1Mbps） | 舵机驱动板 A：PA2→板子 TX，PA3→板子 RX，GND→GND（微雪这块板是 TX 接 TX、RX 接 RX） | **拔掉 P4 跳线帽**（RS232/RS485 选择）；驱动板跳线帽放 A；驱动板电源 12V |
| ↳ 夹爪支路 | — | 驱动板接口 2 → **6V 降压模块**（微雪 DC Buck Adapter 6V）→ SC09 | 夹爪 ID 必须改成 4（`GRIP_ON_ST_BUS 1`）；改 ID 前不要插上 |
| （备用）SC09 单独总线 | PC6 = TX，PC7 = RX（USART6，1Mbps） | 第二块舵机驱动板（6V 供电） | 只有 `GRIP_ON_ST_BUS 0` 时用；不能插 OV 摄像头模块（同引脚） |
| 摄像头 | PB10 = TX，PB11 = RX（USART3，115200） | 相机的 RX/TX | **拔掉 P2 跳线帽** |
| 日志/调试 | PA9/PA10（USART1） | 板载 USB 转串口 | — |
| 陀螺仪 | PB8 = SCL，PB9 = SDA | GY-521（MPU6050）模块：VCC→3.3V，GND→GND | XDA/XCL/AD0/INT 不接；默认已启用 |
| 激光测距 ×8 | PB8 = SCL，PB9 = SDA（同一条 I2C） | TCA9548A 多路开关（A0/A1/A2 接 GND，地址 0x70）；8 个 VL53L0X 模块分别接开关的 SD0/SC0 … SD7/SC7 | 模块 VIN 接 3.3V 或 5V（看模块说明），XSHUT/GPIO1 不接。8 个 VL53L0X 地址都是 0x29，所以必须经过多路开关 |
| 一键启动 | KEY0（PE4） | — | 规则要求车上有明确标识；可外接按钮并联 |
| 切换启停区 | KEY1（PE3） | — | 屏幕/日志显示 READY Z1 或 Z2 |

**三条安全规则：**

- 所有模块必须**共地**。
- SC09 只能接 6V，**绝对不能直接插到 12V 的驱动板接口上**，中间必须串 6V 降压模块。`sscan` 会显示夹爪电压，超过 7.5V 会报警。
- TX 接对方 RX，RX 接对方 TX。

## 5. 上车调试顺序（每步都有"通过标准"，过了再做下一步）

先把车架空（轮子离地），串口助手打开。

### 5.1 驱动板通信

| 命令 | 通过标准 |
|---|---|
| `i2c` | 能看到 `0x34`（驱动板）。看不到：查接线、驱动板供电、GND |
| `bat` | 电池电压合理（3S 满电约 12600 mV） |

### 5.2 轮子接线与方向 → 改 `WHEEL_CH_INIT`、`WHEEL_SIGN_INIT`

| 命令 | 做法 |
|---|---|
| `mot 1 15` … `mot 4 15` | 记下每个通道 M1~M4 分别是哪个轮子、往前还是往后转 |
| 改 config | 填进 `robot_config.h`，重新编译下载 |
| `wheel` | 应依次看到"左前、右前、左后、右后"**向前**转 |

如果某个轮子越转越快停不下来：编码器极性反了，把 `MOTOR_DRV_ENC_POLARITY` 改成 1；也要核对编码器 A/B 线序。

### 5.3 编码器每圈脉冲 → 改 `ENC_COUNTS_PER_WHEEL_REV`

1. 用 `enc` 记下读数。
2. 用手把左前轮向前转 10 圈。
3. 再 `enc`，左前读数的差值 ÷ 10 就是每圈脉冲数。
4. 四个轮子都测一下取平均。

### 5.4 走直线、横移、转圈 → 改 `FWD_SCALE`、`STRAFE_SCALE`、`ROT_SCALE`

车放到地上，四周留空间。

| 命令 | 做法 | 修正公式 |
|---|---|---|
| `pose 0 0 0`，`move 1000 0 0` | 前进 1 米，用卷尺量实际距离 | `FWD_SCALE` = 实际 ÷ 1000 |
| `move 0 1000 0` | 向左横移 1 米 | `STRAFE_SCALE` = 实际 ÷ 1000（麦轮横移打滑多，常见 0.85~0.95） |
| `imu off`，`spin 2` | 先临时关掉陀螺仪，原地转两圈 | `ROT_SCALE` = 旧值 × 实际转的角度 ÷ 720 |

每次改完重新测，直到误差 < 1%。测完 `imu on` 打开陀螺仪。

### 5.4.1 陀螺仪 → 改 `IMU_YAW_SIGN`、`IMU_SCALE`

上电后车先**静止约 1 秒**（测零漂），串口出现 `imu: 就绪` 才算接好。

| 命令 | 做法 | 通过标准 / 修正 |
|---|---|---|
| `i2c` | 扫描总线 | 能看到 `0x68`（陀螺仪）和 `0x34`（驱动板） |
| `imu` | 车静止时看读数 | 当前角速度 0、零漂绝对值一般 < 3°/s |
| `imu 0`，手把车**逆时针**（从上往下看）转约 90°，`imu` | 检查方向 | 累计应约 **+90**；是 -90 就把 `IMU_YAW_SIGN` 改成 -1 |
| 车侧面贴着一条直线（胶带）摆好，`spin 2` | 车按陀螺仪转两圈后停下，看车侧面和直线差多少度 | `IMU_SCALE` = 旧值 × 实际角度 ÷ 720（多转了 10° 就是 × 730/720） |

陀螺仪比例误差一般在 ±3% 以内，但 3% 在转 180° 时就是 5°，所以这一步不能省。标定后重复 `spin 2` 三次，每次偏差都 < 2° 才算通过。

> 如果比赛中陀螺仪掉线（杜邦线松了），程序会在约 0.1 秒内发现，自动改用轮子算朝向，串口会提示。所以 `ROT_SCALE` 也要标定好，作为后备。

### 5.5 舵机

> **第一次接舵机，先用「舵机测试模式」**：烧录 `SmartCar_F407_舵机测试.hex`（或把 `robot_config.h` 里 `SERVO_TEST_MODE` 改成 1 再编译）。这个模式上电时机械臂不上力、不动，只用下面的命令：
> `sscan` 扫描总线上有哪些 ID（不动）；`snudge <ID> <步数>` 从当前位置慢慢转一小步（最多 ±200 步 ≈ ±17°）；`sfree <ID>` 卸力。
> 测完、ID 改好、零位标定好之后，再烧正常版本 `SmartCar_F407.hex`：正常版本上电会自动收到折叠姿态，没标定时这一下动作很大。

1. **改 ID**：一次只接一个 ST3215，
   - 回转保持 1（出厂即 1）；
   - 肩：`sid st 1 2`；
   - 肘：`sid st 1 3`。
   - SC09 夹爪（和 ST3215 在同一条总线上，出厂也是 ID 1，所以必须改）：**先拔掉 3 个 ST3215 的线**，只把 接口2 → 6V 降压模块 → SC09 接上，`sscan` 能看到 ID 1，再 `sid sc 1 4`。程序检测到 ST3215 还在线时会拒绝改。改完再把 ST3215 插回去，`sscan` 应该看到 ID 1、2、3、4 共 4 个。
2. **检查连接**：`sping`，四个都在才继续。
3. **示教零位** → 改 `*_ZERO_RAW` 和 `*_DIR`
   - `storque 0`（卸力，可以用手掰）。
   - 把机械臂摆成"大臂水平向前、小臂和大臂成一条直线、整体指向车头"。
   - `sread`，记下三个读数，就是三个 `ZERO`。
   - 再把每个关节往"抬起/向左"方向掰一点，`sread`：读数变大，`DIR=+1`；变小，`DIR=-1`。
4. **夹爪**：`sfree g` 卸力后手动张到能套住 Ø30 顶部、合到夹紧，分别 `sread` → 填 `GRIP_RAW_OPEN`、`GRIP_RAW_CLOSE`。空着合到底的读数 → `GRIP_RAW_EMPTY_CLOSED`。也可以用 `snudge g <步数>` 一点点转（±60 步以内，1024 步 = 300°）。
5. **测试**：`storque 1`，然后
   - `arm 200 -45 120`（夹持中心到车头前方 20cm、高 12cm 处）：用尺量，误差应在几毫米内；
   - `slot 0 p`、`slot 0 t`：放进、取出载物槽。
6. **出发姿态**：`fold` 后量整车，必须 ≤ 300×300×400（含线）→ 改 `FOLD_*_RAW`。

> **机械注意：** 小臂+夹爪约 166mm，比大臂 90mm 长很多。机械臂伸到车上近处的载物槽时：
> - 大臂要向后仰到约 150°；
> - 小臂向前下折到约 -145°。
>
> 请确认肩、肘舵机支架能转到这个角度而不互相干涉（10月7日动画里就是靠让位 4mm、加隔套 11mm 才不碰的）。

### 5.6 摄像头（选定型号后）

相机程序按 `vision.h` 的协议发数据：

```
$QR,156+123+516+231
$TT,颜色,稳定,dx,dy
$RING,1,dx,dy,dth
```

没有相机时也能先测：

- 用 USB 转 TTL 模块接 PB10/PB11，在串口助手里手动发这些行。
- 或者用 `task 156+123+516+231` 命令跳过读码。注意：转盘取料仍需要 `$TT` 数据。

### 5.6.1 激光测距（避障）

**安装位置**（车体坐标：x 向前、y 向左，单位 mm；改了位置要同步改 `robot_config.h` 的 `TOF_LAYOUT_INIT`，顺序就是多路开关通道 0~7）：

| 通道 | 位置 | 朝向 |
|---|---|---|
| 0 / 1 | 车头，左右各离中线 70 | 正前 |
| 2 / 3 | 车尾，左右各离中线 70 | 正后 |
| 4 / 5 | 左侧，前后各离中线 30（两个轮子之间） | 正左 |
| 6 / 7 | 右侧，前后各离中线 30 | 正右 |

高度离地约 50mm（障碍物高 100mm）。**传感器要向上仰约 12°**：VL53L0X 视场有 25°，水平装时视场下边缘在约 23cm 处就扫到地面，会把地面当成障碍物；仰 12° 后视场下边缘基本水平。

**上车检查**：

1. 串口输入 `tof`：上电日志应有“tof: 8/8 个测距传感器就绪”；每个传感器打印一行读数。
2. 用手或障碍物（最好就用黑色 φ50 的圆柱）依次挡每个传感器，距离 10~50cm，读数应跟着变，误差在 ±3cm 以内。0 表示没看到东西。
3. 黑色障碍物在多远能稳定测到，要实测：仿真里假设最远 70cm，程序只用 60cm 以内的读数（`TOF_MAX_RANGE_MM`）。如果实测黑色只能到 40cm，把这个值改成 400，再跑一遍仿真看会不会撞。
4. 把车放在场地上、四周放几个障碍物，比赛模式跑一遍，日志里会打印“避障：发现障碍物 #k (x, y)”，看坐标对不对。`tof clear` 清空已发现的障碍物。

### 5.7 场地坐标

到场地后量出以下位置，改 `field.c` 开头的数字：

- 转盘圆心（`TT_CENTER_*`）
- 转盘上物料半径
- 二维码板位置
- 两个加工区三个圆环的中心，以及**编号顺序**

### 5.8 整场

1. KEY1 选启停区。
2. KEY0 启动。
3. 串口日志里每个阶段会打印"==== 某阶段 开始（已用 xx 秒）===="，方便找慢在哪里。
4. 任何时候在串口输入 `s` 回车，就会急停。

## 6. 程序是怎么组织的（详细讲解见后续对话）

```
 mission.c  整场流程（像菜谱一样一步步写）
     │ 调用
 nav.c 走位/路线     arm.c 机械臂动作     vision.c 相机     display.c 屏幕
     │                   │
 chassis.c 麦轮       bus_servo.c 舵机协议
     │                   │
 motor_drv.c 驱动板      │
     └──────── port_stm32.c（引脚/串口/I2C）────────┘
```

- **主循环**：`sys_poll()` 每 20ms 做一次底盘控制（读编码器、算位置、发轮速），并接收相机数据和串口命令。所有"等待"的地方都在不停调用它，所以车在动的同时程序也能做别的事。
- **开车和机械臂同时动**：同一加工区内，从一个圆环挪到下一个圆环时，机械臂同时从载物槽取下一个物料。规则规定跨区时物料必须在车上，所以跨区前一定先放回载物槽。
- **相机校正**：每到一个圆环，相机看到的偏差用来修正放置位置，同时把车的里程计"拉回"正确位置，误差不会越积越多。

## 7. 电脑模拟器

模拟器把 `Core/Src` 里的比赛代码（除了直接操作硬件的 `port_stm32.c`、`main.c` 和 HAL 库）原样编译到电脑上运行，电机、舵机、转盘、摄像头、场地由模拟器代替，另有独立的“裁判”按规则检查压线、放置偏差并估分。跑完生成回放，用浏览器打开 `sim/三维仿真回放.html` 看三维动画（小车和机械臂是 SolidWorks 装配体模型）。

详细图文说明见分享包最外层的 `使用说明.html`。

### Windows

1. 第一次：双击分享包最外层的 `一键安装并运行仿真.bat`，它会把 C 编译器 w64devkit 装到 `C:\w64devkit`（STM32CubeIDE 里的编译器只能编译单片机程序，不能用）。
   没有分享包时，也可以自己从 <https://github.com/skeeto/w64devkit/releases> 下载 `w64devkit-x64-*.exe`，解压到 `C:\w64devkit`。
2. 以后每次改完代码或 `robot_config.h` 的参数并保存，双击 `sim\编译并运行仿真.bat`：重新编译 → 输入任务码和启停区（直接回车用默认）→ 1~2 秒跑完一场 → 自动打开三维回放。
3. 代码有语法错误时会停在编译这一步，指出第一处错误在哪个文件第几行，并列出常见错误的改法；这时不会打开回放（否则看到的是旧结果）。
4. 双击 `sim\批量测试.bat`：先重新编译，再跑几十场（理想标定、打滑、装/不装陀螺仪、相机看不到圆环），结果存到 `sim\批量测试结果.txt`。

回放页右上角写着“本次仿真运行于 …”，可以确认看到的是不是最新结果。别人发来的 `replay_任务码_zoneN.js` 可以用回放页右上角“打开其他回放数据”查看。`sim/示例输出/` 里有一份现成的结果。

> 不要直接双击 `sim.exe` 看结果：它是上一次编译出来的，不含之后改的代码（现在双击它也会自动转去运行 `编译并运行仿真.bat`）。

### Mac / Linux

在 `sim` 目录执行 `make`（需要 gcc 或 clang），或用分享包里的 `运行仿真_Mac或Linux.sh`。改了二维回放页面 `replay_template.html` 后，先运行 `python gen_template.py` 重新生成 `replay_template.h`；三维回放页面的源码在 `sim/三维回放源码/`。

| 命令 | 作用 |
|---|---|
| `./test_task` | 任务码解析单元测试 |
| `./sim` | 交互运行：输入任务码和启停区，跑一整场并生成回放 |
| `./sim 156+123+516+231 2` | 指定任务码和启停区 |
| `./sim 156+123+516+231 1 2 1` | 打滑 2%、装陀螺仪 |
| `./sim 156+123+516+231 1 0 0 2222` | 第 5 个参数：障碍物摆法编号（同一编号 = 同一种摆法，方便复现）；`0` = 不放障碍物；不写 = 每次随机 |
| `./sim 156+123+516+231 1 0 0 2222 7` | 第 6 个参数：随机种子（转盘方向、物料顺序） |
| `./sim --batch` | 批量测试并汇总（含一组随机障碍物） |
| `./sim --obs 400` | 跑 400 场随机障碍物，只打印汇总：撞障碍物、压线、超时、发现率、误报 |

模拟器模拟了：底盘与编码器、驱动板、舵机（含加减速）、夹爪夹住/松开、转盘转动和停顿、第二批补料、摄像头输出、随机障碍物和激光测距读数、压线检查（越出车道即本轮结束）、车身碰障碍物检查、按评分表估分。

Windows 上交互运行时会多问一句“障碍物”：直接回车 = 随机摆 1~3 个（每次不同，结果里会写“摆法编号”）；输入 0 = 不放；输入编号 = 复现那一场。

### 7.1 避障是怎么做的，仿真里效果如何

1. **障碍物**：每场随机放 1~3 个黑色 φ50×100 圆柱，放在三条横道、三条竖道的中线附近（左右 ±100mm），但不放在车必须停的地方（读码、取料、6 个放料位、启停区周围 33cm 内），也不把路全堵死。
2. **测距模拟**：每个传感器在 25° 视场里打 7 条射线，取最近的回波；能被看到的有障碍物、地上的物料、转盘、场地围挡。黑色最远 70cm，有 ±1.5% 的噪声和 1% 的丢失。
3. **单片机里的处理**（`obstacle.c`）：
   - 读数能用已知的围挡、转盘、加工区解释的，扔掉（视场斜着扫到围挡时读数会比正前方短，不扔掉就会以为车道上有东西）；
   - 按传感器位置和车的位姿算出障碍物在场地上的位置；同一位置连续 2 次才确认；
   - 视场 25° 意味着 50cm 外看到的东西横向可能偏 11cm，所以每个障碍物记一个“可能偏多少”，规划时连这个范围一起让开，越看越近、范围越小；
   - 路线被挡：先刹停，停稳后重新规划，绕到别的车道；实在没路时逐步减小让开的余量再试。
4. **裁判**：`world.c` 按规则尺寸和车身真实外形（234×296）独立判压线，不用 `field.c`；车身碰到障碍物会记下时刻，三维回放里障碍物变红。

**传感器布置对比**（`--obs 400`，同样 400 场随机障碍物）：

| 布置 | 撞障碍物 | 压线 | 平均分 |
|---|---|---|---|
| 4 个（每面中间 1 个） | 36 场（9%） | 0 | 约 166 |
| **8 个（现在的布置）** | **10 场（2.5%）** | 1 场 | **约 165** |
| 8 个，侧面两个各向外偏 10° | 7 场 | 3 场 | 约 158 |
| 12 个（再加 4 个 45° 斜角） | 1 场（0.25%） | 1 场 | 约 165 |

4 个的平均分不低，是因为估分里没有“碰障碍物扣分”这一项（规则原文没写怎么罚）；碰到障碍物把它推走、卡住轮子，实际后果难说，所以用 8 个。剩下的碰撞几乎都是同一种情况：障碍物在拐角斜前方很近的地方，侧面传感器只有两个轮子之间 60mm 的位置可装，近处看不到斜前方。斜角传感器能解决，但车角是轮子，得在轮子上方做支架，机械上能装再说。

不要为了分数去改 `sim` 里的 `world.c`、`port_sim.c`、`sim_main.c`：它们是“场地 + 裁判”。改了参数或代码后，先在模拟器里跑一遍，再下载到车上。

## 8. 已知风险与建议

1. **时间**：模拟用时约 166~178s。提速办法：
   - 调高 `NAV_VMAX_MMPS`、`ARM_SPEED_RAW_PER_S`（需实测稳定性）；
   - 减少相机等待；
   - 转盘取料时提前把机械臂停在取料点上方。
2. **陀螺仪**：已加 GY-521（MPU6050），接法见第 4 节，标定见 5.4.1。线要用螺丝端子或焊接，杜邦线在振动下容易松。板载 ST480MC 磁力计离电机近、不可靠，程序没用它。
3. **启停区只有 2mm 余量**：出发包络约 296×233mm，启停区 300×300，左右各只剩 2mm，返程时车身很难完全停进去。建议机械上把轮外侧宽度减到 280mm 以内。
4. **载物槽**：内腔约 Ø82，物料底 Ø50，在槽里能滑动 ±16mm，而夹爪对 Ø30 顶部只有约 ±8mm 容差。建议加 Ø52 定位沉台。
5. **避障还没上过实车**：VL53L0X 驱动没在硬件上跑过；黑色障碍物实际能测多远、地面反射、多个传感器之间的串扰，都要按 5.6.1 实测。仿真里还有约 2.5% 的场次碰到障碍物（原因见 7.1）。
6. **规则边界**：
   - "粗加工区取回"与"不得再次移动已放置物料"的边界，请向赛事方确认；
   - 圆环评分按"垂直看到外圈"换算成偏差（1 环 ≤1.5mm），以裁判解释为准。
